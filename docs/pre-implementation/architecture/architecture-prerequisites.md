# 企业级统一监控平台技术架构前置决策

## 1. 文档定位

本文记录产品原型设计阶段已收敛的架构前置问题，用于启动“技术架构与设计”阶段。后续总体架构、领域模型、数据库设计、接口设计、权限模型、日志/指标存储方案和集成方案应以本文为输入。

## 2. 已确认决策

| 编号 | 主题 | 决策 | 架构影响 |
| --- | --- | --- | --- |
| AD-01 | 应用资产与 CMDB | 当前没有统一应用资产库，也没有统一 CMDB；微服务应用部分使用 Nacos 管理配置，单体应用和负责人信息仍分散维护 | 一期需要平台内置应用资产、负责人、业务线、环境、服务器映射和接入状态管理；数据模型需预留外部资产库/CMDB 同步字段 |
| AD-02 | 负责人来源 | 各系统负责人管理自己负责的系统 | 一期负责人可由平台维护，需支持手工维护、批量导入和后续外部主数据同步 |
| AD-03 | 通知渠道 | 一期优先使用邮件 | 通知渠道模型仍需支持多渠道扩展，但一期发送链路、模板、通知记录和失败处理优先围绕邮件落地 |
| AD-04 | 日志保留 | 各应用日志保留周期不统一，至少保留 1 个月，部分低频应用可能保留 1 年 | 日志存储需要支持按应用/环境配置保留周期，技术方案应考虑冷热分层、索引生命周期和成本控制 |
| AD-05 | 敏感字段脱敏 | 公司暂无明确统一文件，但需要预留扩展空间 | 日志查询、导出、复制、明文查看需经过脱敏策略引擎；脱敏规则应可配置、可审计、可按字段类型扩展 |
| AD-06 | 组织隔离 | 需要支持多业务线独立管理 | 权限模型需包含业务线维度；菜单、应用、指标、日志、告警、报表和导出均需按业务线和应用授权过滤 |
| AD-07 | 外部系统集成 | 一期不接入工单系统、事件管理系统或 IM 机器人，但保留扩展空间 | 告警事件、通知事件、处理记录和审计事件应设计统一事件模型，预留 Webhook/API/消息事件出口 |
| AD-08 | 一期接入范围 | 优先接入 ACE、iPro、CMS 等应用，约 20 台服务器，覆盖 Kafka、PostgreSQL 等关键中间件/数据库 | 容量评估、采集频率、指标维度、默认告警规则和演示数据应围绕该规模设计，并保留横向扩展能力 |
| AD-09 | 业务指标范围 | 业务指标优先围绕物流、采购相关场景梳理 | 业务指标模型需支持业务域、指标口径、数据来源、刷新周期、负责人和权限范围 |

## 3. 对技术架构设计的直接要求

1. 平台需要自建轻量应用资产目录，至少覆盖应用、系统、业务线、环境、负责人、部署服务器、接入状态和数据源绑定关系。
2. 权限设计不能只停留在角色级别，必须支持“角色 + 应用授权 + 业务线隔离 + 操作权限 + 敏感字段权限”的组合判断。
3. 通知模块一期以邮件为主，但通知渠道、模板、发送记录和失败原因应保持渠道无关抽象。
4. 日志方案必须支持应用级保留周期，默认不少于 1 个月，并支持更长周期应用的存储策略。
5. 脱敏能力需要前置到日志查询、日志导出和审计设计中，不宜作为后期页面逻辑补丁。
6. 告警、通知、处理、导出、权限变更和接入配置变更需要统一审计事件。
7. 接入方案需要覆盖应用、服务器、Kafka、PostgreSQL，后续再扩展更多中间件和数据库类型。
8. 外部工单、事件管理和 IM 机器人暂不实现，但告警事件与处理记录需能被外部系统订阅或拉取。

## 4. 仍需架构阶段细化的问题

| 编号 | 问题 | 建议产出 |
| --- | --- | --- |
| AP-01 | ACE、iPro、CMS 的正式应用编码、负责人、业务线、环境和部署拓扑 | 一期接入清单和应用资产初始化模板 |
| AP-02 | 20 台服务器的主机名、IP、环境、部署应用、Agent 状态和负责人 | 服务器资产模型和接入实施清单 |
| AP-03 | Kafka、PostgreSQL 的关键指标和默认阈值 | 中间件/数据库监控指标字典和告警规则模板 |
| AP-04 | 物流、采购业务指标口径 | 业务指标字典、数据来源和刷新策略 |
| AP-05 | 邮件服务配置和模板规范 | 邮件通知技术方案和模板清单 |
| AP-06 | 第一批敏感字段脱敏规则 | 脱敏策略配置表和安全评审清单 |

## 5. 阶段结论

产品原型设计阶段可以按“带问题通过”进入技术架构与设计阶段。上述已确认决策不阻塞总体架构启动；第 4 节问题应在详细设计冻结前完成收敛。
