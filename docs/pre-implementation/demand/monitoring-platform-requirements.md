| 外部集成 | 一期不接入工单系统、事件管理系统或 IM 机器人，但接口和事件模型需预留扩展空间 |
| 一期接入对象 | 优先接入 ACE、iPro、CMS 等核心应用，约 20 台服务器，并覆盖 Kafka、PostgreSQL 等关键中间件/数据库 |

## 2. 建设背景

当前公司应用数量不断增加，应用运行状态、服务器资源、日志、异常告警等信息分散在不同系统或由不同团队维护，导致故障发现不及时、定位链路长、责任人通知不准确、历史数据难以沉淀。

需要建设一个统一监控平台，将公司所有应用的运行数据集中采集、展示、分析和告警，形成从问题发现、通知、处理、跟踪到复盘的完整闭环。

## 3. 建设目标

1. 统一接入公司所有应用、服务器、数据库、中间件、容器、日志等监控信息。
2. 支持实时查看服务器负载、应用运行状态、接口健康、错误日志、业务指标等关键数据。
3. 支持自定义监控指标、阈值规则、告警级别、通知渠道和负责人。
4. 告警触发后自动通知相关负责人，并支持告警确认、处理、升级和恢复通知。
5. 提供统一检索、趋势分析、报表统计和故障追踪能力。
6. 降低人工巡检成本，提高故障发现速度和系统稳定性。

## 4. 建设范围

### 4.1 纳入范围

- 服务器基础资源监控：CPU、内存、磁盘、网络、进程、端口等。
- 应用运行监控：应用存活状态、实例数量、启动时间、版本、健康检查、请求量、错误率、响应耗时等。
- 应用日志查询：按应用、环境、实例、关键字、日志级别、时间范围检索日志。
- 中间件监控：Redis、MQ、Nginx、网关、任务调度、缓存等。
- 数据库监控：连接数、慢 SQL、QPS、锁等待、主从状态、容量等。
- 业务指标监控：订单量、支付成功率、任务积压量、数据同步延迟等。
- 告警管理：规则配置、告警触发、通知、确认、处理、关闭、升级。
- 权限管理：用户、角色、应用负责人、数据权限、操作权限。
- 数据看板：全局大盘、应用大盘、服务器大盘、告警大盘、业务大盘。

### 4.2 暂不纳入范围

- 自动修复和自动扩容能力可作为二期建设内容。
- 完整 APM 分布式链路追踪可作为独立模块逐步建设。
- 安全审计、漏洞扫描、资产盘点不作为本期核心功能，但预留集成入口。

## 5. 用户角色

| 角色 | 主要诉求 |
| --- | --- |
| 平台管理员 | 管理平台配置、用户权限、全局指标、数据源、通知渠道 |
| 运维/SRE | 监控基础设施、分析故障、处理告警、维护告警规则 |
| 应用研发负责人 | 查看负责应用状态、日志、错误、性能指标和告警 |
| 业务负责人 | 关注业务指标、服务可用性和重大故障通知 |
| 测试人员 | 在测试环境查看应用状态、日志和接口异常 |
| 值班人员 | 接收告警、确认告警、跟进处理和升级问题 |

## 6. 总体功能架构

平台建议划分为以下核心模块：

1. 首页总览
2. 应用监控
3. 服务器监控
4. 日志中心
5. 指标中心
6. 告警中心
7. 通知与值班管理
8. 报表与分析
9. 系统管理
10. 接入与集成管理

## 7. 功能需求

### 7.1 首页总览

首页需要让用户快速判断公司整体系统健康状况，并以排障视角优先呈现当前异常、影响对象、负责人和处理入口。

#### 功能点

- 展示全局健康状态：正常、预警、异常、严重。
- 展示应用总数、在线应用数、异常应用数、服务器总数、异常服务器数。
- 展示当前活跃告警数量，并按严重级别分类。
- 展示最近 24 小时告警趋势。
- 展示 TOP 异常应用、TOP 高负载服务器、TOP 慢接口。
- 展示待处理问题队列，包括异常对象、告警级别、负责人、持续时间和快捷处理入口。
- 支持从异常对象直接跳转应用详情、服务器详情、告警详情、日志查询和指标趋势。
- 展示核心业务指标卡片，例如订单量、支付成功率、任务积压量。
- 支持按环境筛选：生产、预发、测试、开发。
- 支持按业务线、部门、应用负责人筛选。

#### 验收标准

- 用户进入平台后 5 秒内能够看到核心健康状态。
- 首页数据刷新周期可配置，默认 30 秒。
- 异常状态支持点击跳转到对应应用、服务器或告警详情。

### 7.2 应用监控

用于集中查看公司所有应用的运行情况。

#### 功能点

- 应用列表：应用名称、应用编码、所属系统、业务线、环境、负责人、运行状态、实例数量、最近发布时间。
- 应用详情：
  - 基本信息：名称、编码、描述、负责人、仓库地址、部署环境。
  - 实例信息：实例 IP、端口、启动时间、运行时长、版本、健康状态。
  - 接口指标：请求量、错误率、平均响应时间、P95、P99。
  - JVM/运行时指标：堆内存、GC 次数、线程数、连接池等，按技术栈适配。
  - 依赖状态：数据库、缓存、MQ、第三方服务等。
  - 最近告警：展示当前应用相关未恢复告警。
- 支持应用健康检查地址配置。
- 支持应用上下线状态识别。
- 支持应用多环境、多实例展示。

#### 验收标准

- 能够按应用名称、负责人、环境、状态快速检索。
- 单个应用详情页能够完整展示应用健康、性能、实例和告警信息。
- 应用异常时能够定位到异常实例或异常接口。

### 7.3 服务器监控

用于查看服务器、虚拟机、云主机或物理机资源使用情况。

#### 功能点

- 服务器列表：主机名、IP、环境、机房/区域、负责人、CPU、内存、磁盘、网络、状态。
- 服务器详情：
  - CPU 使用率、负载、核心数。
  - 内存使用率、Swap 使用情况。
  - 磁盘使用率、磁盘 IO、挂载点容量。
  - 网络入流量、出流量、连接数、丢包率。
  - 进程列表、端口监听、关键进程状态。
  - 主机最近告警和历史趋势。
- 支持服务器分组，例如按业务线、应用、环境、机房分组。
- 支持资源趋势查看：最近 1 小时、6 小时、24 小时、7 天、30 天。

#### 验收标准

- 能够查看任意服务器当前负载和历史趋势。
- CPU、内存、磁盘等核心指标支持配置告警规则。
- 服务器异常时能够关联展示部署在该服务器上的应用。

### 7.4 日志中心

用于统一检索和分析应用日志。

#### 功能点

- 日志查询条件：
  - 应用名称
  - 环境
  - 实例 IP
  - 日志级别：DEBUG、INFO、WARN、ERROR、FATAL
  - 时间范围
  - 关键字
  - Trace ID / Request ID / 用户 ID / 订单号等业务字段
- 支持日志上下文查看，例如查看命中日志前后 N 行。
- 支持日志高亮、错误堆栈折叠和展开。
- 支持日志导出，导出权限需要受控。
- 支持常用查询条件保存。
- 支持从告警详情跳转到关联日志。
- 支持错误日志统计，例如按应用、错误类型、时间趋势聚合。

#### 验收标准

- 用户能够在指定时间范围内按关键字查询日志。
- ERROR 级别日志可以按应用和时间趋势统计。
- 告警详情能够关联到对应时间段、应用和实例的日志查询结果。

### 7.5 指标中心

用于统一管理技术指标和业务指标。

#### 指标类型

- 系统指标：CPU、内存、磁盘、网络、进程。
- 应用指标：QPS、响应时间、错误率、可用率、线程池、连接池。
- 中间件指标：队列积压、缓存命中率、连接数、消费延迟。
- 数据库指标：连接数、慢查询、QPS、TPS、锁等待、容量。
- 业务指标：订单量、支付成功率、注册数、同步延迟、任务失败数。

#### 功能点

- 指标注册：指标名称、指标编码、指标类型、单位、采集周期、所属应用、说明。
- 指标查询：按应用、环境、指标类型、时间范围查询趋势。
- 指标对比：支持同一指标跨应用、跨实例、跨时间对比。
- 指标聚合：平均值、最大值、最小值、P95、P99、同比、环比。
- 指标收藏：用户可收藏常用指标。
- 指标权限：不同角色只能查看授权范围内指标。

#### 验收标准

- 新指标接入后可以在平台查询趋势数据。
- 指标能够作为告警规则的数据来源。
- 业务指标支持自定义单位和展示名称。

### 7.6 告警中心

告警中心是平台的核心闭环模块。

#### 告警规则配置

一期告警规则以简单阈值规则为主，支持选择单个监控对象或对象范围、单个指标、比较条件、阈值、持续时间和通知对象。复杂组合条件、动态阈值、告警合并、静默和升级策略可作为二期增强。

规则需要支持以下配置项：

| 配置项 | 说明 |
| --- | --- |
| 规则名称 | 告警规则名称 |
| 监控对象 | 应用、服务器、数据库、中间件、业务指标 |
| 指标 | 选择具体监控指标 |
| 环境 | 生产、预发、测试、开发 |
| 触发条件 | 一期支持大于、小于、等于、不等于；包含、不包含、连续异常作为后续增强 |
| 阈值 | 告警触发阈值 |
| 持续时间 | 条件持续多久才触发，避免瞬时抖动 |
| 检测周期 | 每隔多久检测一次 |
| 告警级别 | 提示、一般、严重、紧急 |
| 生效时间 | 全天或指定时间段 |
| 静默策略 | 二期增强，指定时间内不重复通知 |
| 恢复条件 | 指标恢复到正常范围后自动恢复 |
| 通知对象 | 一期支持负责人和值班组，指定用户、部门群作为后续增强 |
| 通知渠道 | 邮件、短信、企业微信、钉钉、电话、Webhook |

#### 告警生命周期

告警状态建议包括：

1. 已触发
2. 已通知
3. 已确认
4. 处理中
5. 已恢复
6. 已关闭
7. 已升级
8. 已静默

#### 告警处理功能

- 告警列表：支持按级别、状态、应用、负责人、时间范围筛选。
- 告警详情：
  - 告警基本信息
  - 触发规则
  - 触发指标值
  - 影响对象
  - 通知记录
  - 处理记录
  - 关联日志
  - 指标趋势图
- 支持告警确认，记录确认人和确认时间。
- 支持填写处理备注。
- 支持告警转派，二期完善转派流程。
- 支持告警升级，例如超过 10 分钟未确认通知上级负责人，二期完善升级策略。
- 支持告警恢复通知。
- 支持告警合并，避免同一问题产生大量重复告警，二期增强。
- 支持告警静默，适用于发布、维护窗口、已知问题，二期增强。

#### 验收标准

- 告警触发后能够在 1 分钟内通知到配置的负责人。
- 告警的触发、通知、确认、处理、恢复全过程有记录。
- 一期支持配置不同级别告警的通知方式和值班组通知对象。
- 同一规则重复触发时一期至少需要避免短时间重复刷屏，完整静默和合并策略二期增强。

### 7.7 通知与值班管理

#### 功能点

- 联系人管理：姓名、部门、手机号、邮箱、企业微信/钉钉账号。
- 负责人配置：应用负责人、服务器负责人、业务负责人。
- 值班组管理：值班组成员、排班周期、工作日/节假日规则。
- 通知模板管理：不同渠道和级别使用不同通知模板。
- 通知渠道管理：邮件、短信、企业微信、钉钉、电话、Webhook。
- 通知失败重试：发送失败后按策略重试。
- 通知升级策略：无人确认时通知二线、主管或群组。
- 通知记录查询：记录发送时间、渠道、接收人、状态和失败原因。

#### 验收标准

- 告警能够根据应用、环境、负责人和值班规则自动匹配通知对象。
- 通知失败时有失败记录和重试机制。
- 值班人员变更后无需修改具体告警规则。

### 7.8 报表与分析

#### 功能点

- 系统可用性报表：按应用、业务线、环境统计可用率。
- 告警统计报表：告警数量、级别分布、处理时长、恢复时长。
- 故障分析报表：高频故障应用、高频告警规则、高频异常服务器。
- 资源使用报表：服务器资源利用率趋势和容量预测。
- 日志错误报表：错误日志数量、错误类型排行。
- 支持日报、周报、月报。
- 支持导出 Excel 或 PDF，导出权限需受控。

#### 验收标准

- 能够按应用、业务线、部门、时间范围生成统计报表。
- 告警处理时效可以被统计。
- 报表数据与平台明细数据一致。

### 7.9 系统管理

#### 功能点

- 用户管理：新增、禁用、编辑用户。
- 角色管理：平台管理员、运维、研发、业务负责人、只读用户等。
- 权限管理：
  - 菜单权限
  - 操作权限
  - 应用数据权限
  - 基于应用授权衍生的日志、指标、告警和关联服务器可见范围
- 组织架构：部门、业务线、团队。
- 字典配置：环境、告警级别、应用类型、服务器类型。
- 操作审计：记录规则修改、告警处理、权限变更、导出操作等。

#### 验收标准

- 普通用户只能查看自己授权范围内的数据。
- 关键操作均可追踪操作人、操作时间和操作内容。
- 用户禁用后不能继续登录平台。

### 7.10 接入与集成管理

#### 功能点

- 数据源管理：Prometheus、Grafana、SkyWalking、OpenTelemetry、ELK、Loki、数据库、云厂商监控等。
- 支持标记应用接入状态：已接入 Prometheus/Grafana、已接入 SkyWalking、未接入监控、仅日志接入、仅指标接入。
- 应用接入管理：接入状态、接入方式、接入文档、接入负责人。
- Agent 管理：Agent 版本、安装状态、心跳状态、采集配置。
- API 接入：提供指标上报、告警回调、日志查询等接口。
- Webhook 集成：支持外部系统接收告警事件。
- 单点登录集成：支持公司统一认证体系。

#### 验收标准

- 新应用能够通过标准流程接入平台。
- 数据源异常时平台能够提示采集异常。
- 接入配置变更有审计记录。

## 8. 非功能需求

### 8.1 性能要求

- 首页核心数据加载时间不超过 5 秒。
- 常规指标查询响应时间不超过 3 秒。
- 日志查询在合理时间范围内响应时间不超过 10 秒。
- 告警检测延迟默认不超过 1 分钟。
- 支持水平扩展，满足应用和指标数量增长。

### 8.2 可用性要求

- 生产环境平台可用率不低于 99.9%。
- 告警通知链路需具备高可用能力。
- 数据采集服务异常时不能影响业务应用运行。
- 平台自身也需要纳入监控。

### 8.3 安全要求

- 支持统一登录和权限控制。
- 敏感日志字段需支持脱敏，例如手机号、身份证号、银行卡号、Token。
- 日志导出、告警规则修改、权限变更需要审计。
- 支持 HTTPS。
- 不允许普通用户查看未授权应用日志和指标。

### 8.4 数据保留要求

| 数据类型 | 建议保留周期 |
| --- | --- |
| 原始指标数据 | 7-15 天 |
| 聚合指标数据 | 6-12 个月 |
| 应用日志 | 至少 1 个月，按应用重要性、使用频率和存储成本差异化配置；低频但有追溯要求的应用可保留 1 年 |
| 告警记录 | 至少 12 个月 |
| 操作审计 | 至少 12 个月 |
| 报表数据 | 至少 12 个月 |

### 8.5 易用性要求

- 常用功能不超过 3 次点击可到达。
- 告警详情需要直接提供指标、日志、责任人和处理入口。
- 看板支持收藏和自定义。
- 时间范围、环境、应用等筛选条件保持统一交互。

## 9. 核心业务流程

### 9.1 应用接入流程

1. 应用负责人提交应用接入申请。
2. 平台管理员或运维审核应用信息。
3. 配置应用基础信息、环境、实例、负责人。
4. 接入指标、日志和健康检查。
5. 配置默认告警规则。
6. 验证数据采集是否正常。
7. 应用正式纳入统一监控。

### 9.2 告警处理流程

1. 平台按照规则检测指标。
2. 指标满足触发条件并持续达到配置时间。
3. 生成告警事件。
4. 根据规则匹配通知对象和值班人员。
5. 通过配置渠道发送通知。
6. 负责人确认告警。
7. 负责人查看指标趋势和关联日志并处理问题。
8. 指标恢复后平台自动标记恢复并发送恢复通知。
9. 处理人补充处理结论。
10. 告警关闭并进入统计分析。

### 9.3 日志查询流程

1. 用户选择应用、环境和时间范围。
2. 输入关键字、Trace ID 或业务字段。
3. 平台返回匹配日志。
4. 用户展开上下文或错误堆栈。
5. 用户可从日志跳转到应用、实例、告警或指标趋势。

## 12. 告警级别建议

| 级别 | 名称 | 场景示例 | 通知方式 |
| --- | --- | --- | --- |
| P0 | 紧急 | 核心业务不可用、生产大面积故障、数据严重异常 | 电话、短信、企业微信/钉钉、群通知，立即升级 |
| P1 | 严重 | 单个核心应用异常、错误率明显升高、数据库主从异常 | 短信、企业微信/钉钉、群通知 |
| P2 | 一般 | 资源持续高负载、接口响应变慢、任务积压 | 企业微信/钉钉、邮件 |
| P3 | 提示 | 短暂波动、容量接近阈值、非核心环境异常 | 邮件或站内通知 |

一期落地阶段优先使用邮件作为正式通知渠道。P0/P1 所需短信、电话、企业微信、钉钉或 IM 群通知能力在数据模型、渠道配置和通知记录中预留，不作为一期强制接入条件。

## 13. 默认告警规则建议

| 对象 | 指标 | 默认规则 |
| --- | --- | --- |
| 服务器 | CPU 使用率 | 连续 5 分钟大于 85% 触发 P2 |
| 服务器 | 内存使用率 | 连续 5 分钟大于 90% 触发 P2 |
| 服务器 | 磁盘使用率 | 大于 85% 触发 P2，大于 95% 触发 P1 |
| 应用 | 健康检查 | 连续 3 次失败触发 P1 |
| 应用 | 错误率 | 连续 5 分钟大于 5% 触发 P1 |
| 应用 | 响应时间 P95 | 连续 5 分钟大于 2 秒触发 P2 |
| 日志 | ERROR 数量 | 5 分钟内超过阈值触发 P2 |
| MQ | 消息积压 | 超过阈值并持续 10 分钟触发 P2 |
| 数据库 | 慢 SQL 数量 | 5 分钟内超过阈值触发 P2 |
| 业务 | 支付成功率 | 连续 5 分钟低于阈值触发 P0/P1 |

## 15. 风险与约束

| 风险 | 说明 | 建议 |
| --- | --- | --- |
| 数据源分散 | 各应用技术栈和监控方式不同 | 制定统一接入规范，兼容主流数据源 |
| 日志量大 | 日志存储和查询成本较高 | 按环境和级别设置采集策略，冷热数据分层 |
| 告警噪音 | 规则不合理会导致频繁告警 | 设置持续时间、静默、合并和分级策略 |
| 责任人不准确 | 应用负责人信息过期会影响通知 | 建立应用资产和负责人定期维护机制 |
| 权限风险 | 日志可能包含敏感信息 | 做好权限隔离、字段脱敏和审计 |
| 平台可用性 | 监控平台自身不可用会影响故障发现 | 平台自身也纳入监控，并保证通知链路高可用 |

## 16. 已确认事项与待确认问题

### 16.1 已确认事项

1. 一期范围按信息架构文档中“导航架构 - 一级导航”的一期规划执行。
2. 核心用户优先级为：应用研发负责人、运维/SRE、业务负责人。
3. 首页采用排障视角，不做纯管理驾驶舱。
4. 一期告警规则先做简单阈值规则，并支持值班组。
5. 一期日志查询支持 Trace ID、上下文、错误聚合、日志导出和从告警跳转日志。
6. 已有数据源包括 Prometheus、Grafana 和少量 SkyWalking，同时存在未接入监控的应用。
7. 一期权限模型按应用授权。
8. 暂无统一应用资产库和统一 CMDB，一期需要平台内维护应用基础信息、负责人、业务线、服务器和接入状态，并为后续对接资产库预留字段。
9. 一期通知渠道优先使用邮件，其他通知渠道作为可扩展能力预留。
10. 日志至少保留 1 个月，部分应用可保留 1 年；敏感字段脱敏规则暂无公司统一文件，需要设计为可配置策略。
11. 一期需要支持多业务线独立管理。
12. 一期不接入工单、事件管理系统或 IM 机器人，但需要预留外部事件、Webhook 或回调扩展能力。
13. 一期优先接入 ACE、iPro、CMS 等核心应用，约 20 台服务器，并覆盖 Kafka、PostgreSQL 等关键中间件/数据库；业务指标优先围绕物流、采购场景梳理。

### 16.2 待确认问题

1. ACE、iPro、CMS 等一期应用的正式应用编码、负责人、业务线、部署环境和服务器映射清单。
2. 物流、采购相关业务指标的第一批指标口径、负责人、数据来源和刷新周期。
3. Kafka、PostgreSQL 等中间件/数据库的一期监控指标范围和告警阈值。
4. 邮件通知的 SMTP/邮件服务配置来源、模板规范和发件账号。
5. 敏感字段脱敏的初始规则清单，例如手机号、身份证号、银行卡号、Token、地址等字段。

## 17. 初步验收标准

1. 平台能够接入至少一批核心应用、服务器、日志和指标数据。
2. 用户能够在首页看到公司整体应用与服务器健康状态。
3. 用户能够按应用查看运行状态、实例状态、性能指标和日志。
4. 用户能够按服务器查看 CPU、内存、磁盘、网络等资源指标。
5. 用户能够配置监控指标告警规则。
6. 指标触发阈值后，平台能够自动生成告警并通知负责人。
7. 告警处理过程能够被记录和追踪。
8. 用户权限能够限制不同人员查看不同范围的数据。
9. 平台关键操作具备审计记录。
10. 平台满足基础性能、可用性和安全要求。
