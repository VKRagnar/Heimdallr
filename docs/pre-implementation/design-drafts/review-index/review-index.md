## 2. 推荐评审顺序

1. 规则预检：确认全局状态、权限矩阵、告警状态机、导出、审计、数据源和应用授权口径无争议。
2. 核心链路评审：按“首页 -> 告警详情 -> 日志查询/错误聚合 -> 应用详情 -> 指标趋势 -> 处理记录”走通。
3. 列表与查询评审：检查应用、服务器、告警、日志、指标、通知记录和导出任务的筛选、表格、状态与权限。
4. 中间件与数据库评审：检查 Redis、MQ、网关、任务调度、数据库实例、慢 SQL、队列积压、连接数、复制延迟和依赖应用联动。
5. 配置与接入评审：检查告警规则、值班组、通知渠道、权限、接入、数据源的表单、抽屉、校验、危险操作和审计。
6. 横向一致性复核：用组件评审清单覆盖导航、筛选、表格、状态、日志、指标、权限、导出、审计、响应式和可访问性。
7. 冻结会签：P0/P1 问题关闭，P2 有责任人与截止时间后，进入设计稿冻结。

## 3. 验收清单

| 编号 | 检查项 | 通过标准 | 结论 |
| --- | --- | --- | --- |
| RI-CORE-01 | 核心排障首屏 | 5 秒内可判断哪里异常、影响什么、谁负责、下一步去哪处理 | 待评审 |
| RI-CORE-02 | 上下文连续 | Trace ID、应用、环境、实例、时间窗口、告警 ID 在跨页面跳转中保留 | 待评审 |
| RI-LIST-01 | 列表扫描效率 | 关键列不可隐藏，默认排序优先风险、级别、更新时间或触发时间 | 待评审 |
| RI-LIST-02 | 查询一致性 | 环境、时间、应用/服务器、负责人、状态、关键字等筛选命名和控件一致 | 待评审 |
| RI-CFG-01 | 配置可验证 | 规则、值班、渠道、权限、接入、数据源配置有校验、预览、测试或保存反馈 | 待评审 |
| RI-CFG-02 | 危险操作完整 | 停用、删除、强制关闭、生产导出、权限变更、密钥更新有二次确认和审计提示 | 待评审 |
| RI-STATE-01 | 状态语义统一 | 正常、预警、异常、严重、未知、未接入、采集异常、P0-P3 文案和 token 一致 | 待评审 |
| RI-PERM-01 | 权限不泄露 | 未授权对象不出现在导航、搜索、下拉、列表、统计、导出、URL 直访中 | 待评审 |
| RI-EXP-01 | 导出受控 | 导出权限、阈值、脱敏、后台任务、有效期、失败原因和审计编号完整 | 待评审 |
| RI-AUD-01 | 审计可追踪 | 告警处理、规则变更、权限变更、导出、敏感字段明文查看均能关联审计信息 | 待评审 |
| RI-DATA-01 | 数据源不误判 | Prometheus/Grafana、SkyWalking、日志源、Agent 异常不被误判为业务正常 | 待评审 |
| RI-MWDB-01 | 中间件和数据库对象可定位 | 中间件/数据库异常可关联应用、服务器、指标、日志/慢 SQL 或队列积压入口 | 待评审 |
| RI-MWDB-02 | 依赖影响范围清晰 | 应用详情依赖区能区分依赖健康、数据源异常、未接入和告警影响范围 | 待评审 |
| RI-A11Y-01 | 响应式与可访问 | 桌面、小屏、键盘焦点、非颜色状态表达、图表摘要均可验收 | 待评审 |

## 4. 冻结条件

- 所有 P0/P1 评审问题关闭。
- P2 问题有责任人、截止时间和不影响冻结的确认。
- 三类设计稿均已按基础约束规则复核。
- 设计稿中的状态、权限、导出、审计、数据源、值班组解析和应用授权口径与 `foundation-rules.md` 一致。
- 设计稿路径、页面范围和验收清单已被产品、研发、测试、运维/SRE 确认。
