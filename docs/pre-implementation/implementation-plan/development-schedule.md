# 一期开发排期与里程碑设计

## 1. 排期假设

| 项目 | 口径 |
| --- | --- |
| 一期目标 | 完成“看见状态、定位问题、触发通知、基础处理闭环、按应用授权隔离” |
| 建设周期 | 建议 12 周，6 个 Sprint，每个 Sprint 2 周，另含第 1 周启动冻结 |
| 优先接入范围 | ACE、iPro、CMS 等核心应用，约 20 台服务器，Kafka、PostgreSQL |
| 一期通知渠道 | 邮件 |
| 核心数据源 | Prometheus/Grafana、日志源、少量 SkyWalking、Agent、Kafka Exporter、PostgreSQL Exporter |
| 二期不纳入 | 工单/事件系统、IM 机器人、复杂规则、动态阈值、完整静默/升级/排班、自动修复、完整 APM 拓扑 |

## 2. 阶段划分

| 阶段 | 周期 | 阶段目标 | 里程碑 |
| --- | --- | --- | --- |
| 阶段 0：启动与冻结 | 第 1 周 | 冻结一期范围、接入清单、指标口径、权限边界和测试策略 | M0：一期范围与接入清单冻结 |
| 阶段 1：底座与资产权限 | 第 2-3 周 | 完成资产、权限、审计、接入状态、核心 API 框架 | M1：资产与权限底座可联调 |
| 阶段 2：数据源与查询链路 | 第 4-5 周 | 完成指标、日志、Agent、Kafka、PostgreSQL 基础适配 | M2：核心数据可查、接入状态可见 |
| 阶段 3：告警与通知闭环 | 第 6-7 周 | 完成简单阈值规则、检测调度、状态机、邮件通知 | M3：告警可触发、可通知、可处理 |
| 阶段 4：前端核心排障链路 | 第 8-9 周 | 完成首页、应用、服务器、日志、指标、告警主链路 | M4：端到端排障链路可演示 |
| 阶段 5：接入试点与验收加固 | 第 10-11 周 | 接入 ACE/iPro/CMS、20 台服务器、Kafka/PostgreSQL，完成权限与异常态测试 | M5：试点范围验收通过 |
| 阶段 6：缓冲与上线准备 | 第 12 周 | 性能、安全、数据质量、运维手册、上线演练和缺陷收敛 | M6：一期上线评审通过 |

## 3. Sprint 计划

| Sprint | 周次 | 研发重点 | 主要交付物 |
| --- | --- | --- | --- |
| Sprint 0 | 第 1 周 | 项目启动、范围冻结、测试矩阵、接入清单确认 | 一期 Backlog、应用/服务器/数据源清单、指标字典初版、验收用例框架 |
| Sprint 1 | 第 2-3 周 | 数据库表结构、用户角色、应用授权、业务线隔离、审计基础、资产维护 | 资产与权限 API、核心表结构、应用/服务器导入、审计事件基础能力 |
| Sprint 2 | 第 4-5 周 | 数据源管理、Prometheus/Grafana、日志源、Agent、Kafka/PostgreSQL 适配 | 数据源配置/校验、接入状态、指标查询、日志查询、Agent 在线状态、默认指标映射 |
| Sprint 3 | 第 6-7 周 | 告警规则、检测调度、状态机、邮件通知、通知记录、值班组基础 | 阈值规则 CRUD、规则启停校验、告警事件、确认/处理中/关闭、邮件发送与重试 |
| Sprint 4 | 第 8-9 周 | 首页总览、应用/服务器列表详情、日志/指标/告警前端主链路 | 排障首页、应用详情、服务器详情、日志上下文、指标趋势、告警详情 |
| Sprint 5 | 第 10-11 周 | 接入试点、端到端联调、权限越权、导出脱敏、数据源异常态 | ACE/iPro/CMS 接入、Kafka/PostgreSQL 模板、导出任务、脱敏策略、验收缺陷修复 |
| Sprint 6 | 第 12 周 | 缓冲、性能压测、安全复核、上线演练、文档交付 | 上线包、回滚方案、运维手册、验收报告、遗留问题清单 |

## 4. 模块优先级

| 优先级 | 模块 | 原因 |
| --- | --- | --- |
| P0 | 应用资产与接入状态 | 缺少 CMDB，权限、日志、指标、告警都依赖应用主线 |
| P0 | 权限与审计 | 应用授权、多业务线隔离、导出和敏感字段必须后端强校验 |
| P0 | 数据源适配层 | Prometheus/Grafana、日志源、Agent、Kafka、PostgreSQL 是核心数据基础 |
| P0 | 日志与指标查询 | 排障链路必须能从告警跳日志、从日志看指标 |
| P0 | 告警规则与状态机 | 一期核心闭环，要求阈值检测、去重、恢复、处理记录 |
| P0 | 邮件通知 | 一期正式触达渠道，必须可测试、可发送、可重试、可追踪 |
| P0 | 首页与告警详情 | 承载“发现问题 -> 定位问题 -> 处理问题”的主入口 |
| P1 | Kafka/PostgreSQL 默认模板 | 一期接入对象包含关键中间件/数据库，专项页面可后置 |
| P1 | 值班组基础能力 | 告警规则需要支持值班组，完整排班和升级二期增强 |
| P1 | 导出、脱敏、敏感明文授权 | 日志导出和敏感字段是安全验收重点 |
| P2 | 保存查询、收藏、共享视图 | 主链路稳定后补齐 |
| P2 | Webhook/API 扩展入口 | 一期预留模型，不做正式外部系统联动 |

## 5. 跨团队依赖

| 依赖方 | 依赖内容 | 期望完成时间 |
| --- | --- | --- |
| 产品/业务 | 一期范围冻结、业务指标口径、页面验收优先级 | 第 1 周 |
| 运维/SRE | Prometheus/Grafana、日志源、SkyWalking、Agent、Kafka/PostgreSQL 接入信息 | 第 1-2 周 |
| 应用团队 | ACE、iPro、CMS 应用编码、负责人、环境、实例、服务器映射、健康检查地址 | 第 1-2 周 |
| DBA/中间件团队 | PostgreSQL、Kafka 指标来源、只读账号、默认阈值、敏感字段范围 | 第 2-4 周 |
| 安全/合规 | 脱敏初始规则、导出策略、敏感字段明文授权口径 | 第 2-5 周 |
| 邮件/基础设施团队 | SMTP 配置、发件账号、网络连通、模板规范 | 第 3-6 周 |
| 测试团队 | 角色矩阵、权限越权用例、状态机用例、数据源异常用例 | 第 2 周起持续 |
| 运维发布团队 | 部署环境、域名/HTTPS、平台自身监控、上线和回滚流程 | 第 9-12 周 |

## 6. 上线准入

1. P0 模块全部完成并通过端到端联调。
2. 试点应用、服务器、Kafka、PostgreSQL 接入状态可见，核心指标和日志可查。
3. 告警从规则配置、检测、邮件通知、确认、处理、恢复、关闭全链路可走通。
4. 权限、导出、脱敏、审计通过专项测试。
5. 数据源异常、Agent 离线、通知失败、无权限、无数据等关键异常态可验证。
6. 平台自身 API、规则检测、通知发送、数据源查询、审计写入已纳入监控。
7. 上线、回滚、运维手册和遗留问题清单完成评审。
