# 测试验收、上线与风险控制实施设计

## 1. 目标与范围

一期测试验收与上线围绕“看见状态、定位问题、触发通知、基础处理闭环、权限隔离、安全审计”展开，确保核心应用、服务器、日志、指标、告警、通知和接入状态可被稳定展示和追踪。

不纳入一期验收：复杂组合规则、动态阈值、智能降噪、完整告警合并/静默/升级/排班日历、工单/事件/IM 正式集成、完整 APM 拓扑、自动修复和中间件/数据库专项一级导航。

## 2. 测试阶段

| 阶段 | 目标 | 准入条件 | 准出条件 |
| --- | --- | --- | --- |
| 需求与设计测试评审 | 确认测试边界、验收口径、风险项 | 需求、原型验收、架构、详细设计完成 | 输出测试范围、专项清单、阻塞问题闭环计划 |
| 单元测试 | 验证核心服务内部逻辑 | 详细设计和接口契约明确 | 核心规则、权限、脱敏、状态机单测通过 |
| 接口与服务测试 | 验证 API、权限、状态流转、异常码 | API 联调环境可用 | P0/P1 接口测试通过，无阻塞缺陷 |
| 前后端集成测试 | 验证页面、接口、状态、跳转上下文 | 前后端主链路联通 | 核心任务路径走通，页面状态覆盖 |
| 数据源联调测试 | 验证 Prometheus、日志源、SkyWalking、Agent、Kafka、PostgreSQL 接入 | 测试数据源和样例应用准备完成 | 接入状态、查询、异常降级符合预期 |
| 专项测试 | 验证权限、脱敏、导出、告警、通知、接入状态 | 主流程基本稳定 | 专项问题清零或有明确豁免 |
| 性能与稳定性测试 | 验证首页、日志、指标、告警检测、通知链路 | 接口功能稳定 | 达到性能目标和容量基线 |
| 安全测试 | 验证越权、敏感信息、密钥、导出、审计 | 权限模型和脱敏策略落地 | 高危问题清零，中危有整改计划 |
| UAT | 业务和运维验收真实工作流 | 测试环境缺陷收敛 | UAT 通过或带问题通过 |
| 预生产演练 | 验证上线流程、数据初始化、监控、回滚 | 发布包冻结 | 演练通过，上线检查清单完成 |
| 生产上线与观察 | 平滑发布、灰度验证、问题响应 | 上线审批通过 | 观察期稳定，移交运维 |

## 3. 专项测试

| 专项 | 重点场景 |
| --- | --- |
| 权限 | 未授权列表/搜索/下拉/统计不可见，URL 直访不泄露对象名称，应用负责人只看授权应用及衍生数据 |
| 脱敏 | 日志查询、上下文、复制、导出、SQL、通知记录、审计记录、密钥配置默认脱敏 |
| 导出 | 异步 `export_task`、权限范围、脱敏、时间/行数/文件大小限制、下载审计、过期不可下载 |
| 告警 | 规则启用校验、持续时间、去重、恢复、重复通知间隔、状态机、失败补偿、审计 |
| 通知 | 邮件渠道测试、SMTP 失败、接收人解析、兜底组、重试、恢复通知、通知记录查询 |
| 接入状态 | 未接入、仅日志、仅指标、采集异常、无近期数据、Agent 无心跳、数据源鉴权失败分开展示 |

## 4. 核心 UAT 场景

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| UAT-01 | 首页发现生产 P1 告警 | 可识别影响对象、负责人、持续时间，并进入告警详情 |
| UAT-02 | 应用负责人排查 ACE 应用错误率 | 可从应用详情进入日志和指标，Trace ID 回显 |
| UAT-03 | 值班人员处理告警 | 可确认、标记处理中、备注、恢复后关闭，全程有记录 |
| UAT-04 | 运维配置 CPU 告警规则 | 规则字段完整，启用前校验通过，触发后通知 |
| UAT-05 | 日志导出 | 有权限可导出授权范围日志，内容脱敏，审计可查 |
| UAT-06 | 测试人员访问生产日志 | 被拒绝，不泄露数据 |
| UAT-07 | 数据源异常 | 页面明确显示数据源异常，不误判为业务异常 |
| UAT-08 | Agent 无心跳 | 服务器详情和接入管理展示异常和最近心跳 |
| UAT-09 | Kafka 积压告警 | 可看到关联 Topic/消费组、影响应用、通知对象 |
| UAT-10 | PostgreSQL 慢 SQL 告警 | 可看到慢 SQL 摘要，明文受控 |
| UAT-11 | 应用授权调整 | 授权后衍生日志、指标、告警、服务器范围正确 |
| UAT-12 | 邮件通知失败 | 告警详情和通知记录展示失败原因和重试状态 |

UAT 通过标准：场景通过率达到 95% 以上，P0/P1 阻塞缺陷全部关闭，P2 缺陷有明确修复计划和上线风险评估，权限、脱敏、导出、告警、通知、接入状态专项必须通过。

## 6. 回滚方案

触发条件包括：核心服务不可用超过 15 分钟、核心页面大面积不可用、权限过滤失效、脱敏失效、大规模误报/漏报、邮件通知链路不可用、数据库变更导致核心数据损坏、数据源适配影响外部系统、审计写入不可用且高风险操作仍可继续、导出越权或导出未脱敏数据。

| 类型 | 策略 |
| --- | --- |
| 前端发布问题 | 回滚前端静态资源到上一稳定版本 |
| 后端服务问题 | 回滚服务镜像或制品到上一稳定版本 |
| 数据库结构问题 | 优先兼容修复；不可修复时按备份和回滚脚本恢复 |
| 配置问题 | 回滚配置中心、通知渠道、脱敏策略、规则模板 |
| 告警误报 | 临时停用新规则或规则检测任务，保留事件数据 |
| 通知异常 | 暂停通知发送任务，切换备用 SMTP 或人工通知 |
| 数据源异常 | 禁用异常数据源绑定，恢复上一配置 |
| 导出风险 | 临时关闭导出入口和导出任务消费 |
| 权限风险 | 切换只读或维护模式，保留管理员修复入口 |

## 7. 风险清单

| 编号 | 风险 | 等级 | 应对措施 |
| --- | --- | --- | --- |
| R-01 | 应用资产和负责人信息不准确 | 高 | 上线前确认 ACE、iPro、CMS 应用编码、负责人、业务线、服务器映射 |
| R-02 | 数据源接入差异大 | 高 | 通过适配层统一状态口径，完成接入验证和异常演练 |
| R-03 | 未接入和采集异常被误判为业务异常 | 高 | 健康状态、接入状态、数据源状态、Agent 状态分开展示和统计 |
| R-04 | 权限过滤不完整 | 高 | 后端统一过滤搜索、下拉、列表、详情、统计、导出、URL 直访 |
| R-05 | 日志敏感字段脱敏不充分 | 高 | 首批规则覆盖个人信息、Token、Cookie、SQL、连接串，全链路脱敏 |
| R-06 | 导出越权或超量 | 高 | 导出异步化、限制范围、下载审计、高风险导出二次确认 |
| R-07 | 告警规则阈值不合理 | 高 | 默认规则先小范围灰度，持续时间和重复通知间隔，上线观察每日复盘 |
| R-08 | 通知对象解析失败 | 高 | 规则对象、负责人、值班组、SRE 兜底逐级解析，失败可见 |
| R-09 | 邮件服务不可用 | 高 | 上线前测试 SMTP，配置重试，准备备用 SMTP 或人工通知预案 |
| R-15 | Kafka/PostgreSQL 共享对象权限边界不清 | 高 | 通过对象依赖裁剪应用相关摘要，全局指标仅 SRE/对象负责人可见 |
| R-17 | 平台自身未纳入监控 | 高 | API、规则检测、通知、数据源适配、审计写入、导出任务纳入监控 |

## 8. 准入与准出

上线准入：核心页面和接口完成 SIT、专项测试、UAT；权限、脱敏、导出、告警、通知、接入状态六类专项无阻塞缺陷；P0/P1 缺陷关闭；生产配置、应用资产、用户权限、数据源、通知渠道、脱敏规则完成初始化；回滚方案经过预生产演练；平台自身监控启用。

上线准出：观察期内无 P0/P1 生产事故；登录、首页、应用、日志、指标、告警、通知、权限均验证通过；未出现未授权数据泄露、脱敏失效、导出越权；遗留问题已归档并明确责任人、优先级和修复计划；运维手册、应急流程、联系人清单完成移交。
