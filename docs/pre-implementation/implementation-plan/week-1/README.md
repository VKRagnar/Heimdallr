# 第一周启动冻结交付物

## 1. 本周目标

第一周对应 Sprint 0，目标不是进入功能开发，而是冻结一期可交付边界、接入对象、指标口径、权限与测试验收输入，确保第 2 周进入资产、权限和审计底座开发时没有关键口径悬空。

本周里程碑为 M0：一期范围与接入清单冻结。

| 交付物 | 文件 | 用途 | 完成口径 | 状态 |
| --- | --- | --- | --- | --- |
| 范围冻结与 Backlog | `scope-and-backlog.md` | 明确一期做什么、不做什么，以及 Sprint 0 任务闭环 | 产品、研发、测试、运维对 P0/P1 范围无分歧 | 已完成 |
| 接入清单 | `access-inventory.md` | 固化 ACE、iPro、CMS、服务器、数据源、Kafka、PostgreSQL 的收集模板 | 能支撑资产初始化、数据源配置和灰度接入 | 已完成 |
| 指标字典初版 | `metric-dictionary.md` | 固化第一批指标编码、来源、采集周期、用途和默认阈值 | 能支撑指标映射、规则模板和验收造数 | 已完成 |

## 3. 文档使用顺序

1. 先读 `scope-and-backlog.md`，确认一期边界、Sprint 0 Backlog 和 M0 冻结评审清单。
2. 再读 `access-inventory.md`，按模板收集 ACE、iPro、CMS、服务器、Kafka、PostgreSQL 和数据源信息。
3. 然后读 `metric-dictionary.md`，把第一批指标编码、默认阈值和待业务确认项转成指标定义与规则模板输入。
4. 最后读 `acceptance-test-matrix.md`，将范围、接入、指标和权限口径映射成测试用例、专项测试和 Sprint 1 准入条件。

## 5. 冻结原则

1. 范围冻结优先级高于细节完美：不影响 Sprint 1 开发的字段可作为待确认项进入风险跟踪。
2. 接入清单必须区分业务健康状态、接入状态、数据源状态和 Agent 状态，避免未接入被误判为业务正常或异常。
3. 指标字典必须先覆盖 ACE、iPro、CMS、约 20 台服务器、Kafka、PostgreSQL 和日志错误聚合。
4. 权限、脱敏、导出和审计从第一周纳入验收口径，不作为上线前补测项。
5. 所有冻结结论需要落到可开发、可测试、可验收的表格，而不是只停留在会议纪要。
