# 应用/服务器/数据源接入清单

## 1. 文档目标

本文用于 Sprint 0 第一周冻结一期接入对象和收集口径，覆盖 ACE、iPro、CMS、约 20 台服务器、Kafka、PostgreSQL、Prometheus/Grafana、日志源、SkyWalking 和 Agent。

清单输出应支撑后续资产初始化、数据源配置、指标映射、默认告警规则、权限授权、脱敏策略和灰度接入。第一周只要求形成可开发、可测试、可验收的初版清单；缺口项必须记录负责人、预计补齐时间和降级策略。

## 6. 接入状态口径

接入状态只描述监控覆盖和采集链路，不直接等同业务健康。未接入、采集异常、业务异常必须分开展示和统计。

| 中文状态 | 建议编码 | 含义 | 统计口径 |
| --- | --- | --- | --- |
| 已接入 | connected | 数据源可用、对象绑定成功、最近有采集数据 | 计入接入完成 |
| 未接入 | not_connected | 未配置数据源或未绑定对象 | 计入接入风险，不计入业务异常 |
| 部分接入 | partial_connected | 仅日志或仅指标接入，能力不完整 | 计入接入缺口 |
| 验证中 | verifying | 配置已收集，正在测试连通性、鉴权、映射和样本数据 | 计入待验证 |
| 采集链路异常 | collector_error | Agent、Exporter 或采集链路异常 | 计入接入异常，不直接触发业务告警 |
| 数据源不可用 | source_unavailable | 数据源不可访问、超时或鉴权失败 | 计入数据源异常 |
| 无近期数据 | no_recent_data | 数据源可用，但对象近期无采集数据 | 计入数据质量风险 |
| 映射无效 | mapping_invalid | 标签、索引、字段映射错误 | 计入配置缺口 |

状态拆分要求：

| 状态类型 | 可选值 | 使用场景 |
| --- | --- | --- |
| 业务健康状态 | 正常、预警、异常、严重、未知 | 描述应用、服务器、中间件、数据库自身运行状态 |
| 接入状态 | 已接入、未接入、部分接入、验证中、采集链路异常、数据源不可用、无近期数据、映射无效 | 描述监控覆盖完整性 |
| 数据源状态 | 正常、异常、超时、鉴权失败、采集延迟 | 描述 Prometheus、日志源、SkyWalking 等底层源可用性 |
| Agent 状态 | 正常、无心跳、版本过低、配置异常、未安装 | 描述主机采集代理状态 |

规则启用约束：

1. 未接入指标或指标无近期采集数据的对象，相关告警规则可保存草稿，不可启用。
2. 数据源异常、查询超时或鉴权失败时，不生成“指标为 0”的业务误告警，只记录检测失败原因和接入异常。
3. Agent 无心跳影响服务器、日志、自采集指标接入状态，但不直接判定业务应用异常。
4. SkyWalking 未接入不影响基础日志和指标能力，只影响链路入口和接口摘要能力。
5. 日志源异常不影响指标告警检测，但影响告警详情关联日志能力。

| 指标源 | Prometheus/Grafana 地址、鉴权、标签映射、绑定对象和最近采集验证结果已记录 |
| 日志源 | 索引模式、字段映射、保留周期、脱敏策略和告警跳日志窗口已记录 |
| SkyWalking | 已接入应用的 Service/Instance 映射和 Trace 跳转入口已记录；未接入应用标记为未接入 |
| Kafka | 集群、Broker、Topic、Consumer Group、Exporter、关联应用和权限范围已记录 |
| PostgreSQL | 实例/集群、库、只读采集账号、Exporter、关联应用、敏感字段口径已记录 |
| Agent | 安装状态、版本、心跳、采集配置版本和异常原因已记录 |

## 8. 缺口风险

| 风险 | 影响 | 第一周处理动作 | 降级策略 |
| --- | --- | --- | --- |
| 应用负责人或业务线不准确 | 告警通知、权限授权和统计口径偏差 | 周二由应用团队确认主备负责人和值班组 | 先按临时负责人接入，M0 记录待补齐 |
| 无统一 CMDB/资产库 | 应用、服务器、实例关系需要人工整理 | 使用本清单作为一期轻量资产目录输入 | 仅冻结 ACE/iPro/CMS 和 20 台服务器范围 |
| Prometheus 标签不统一 | 指标映射失败，规则无法启用 | 周四校验 app、env、instance、hostname 标签 | 为首批应用建立单独映射配置 |
| 日志字段或索引不统一 | 日志检索、Trace ID 跳转和告警关联日志失败 | 收集标准字段映射和索引模式 | 先支持按应用、环境、时间、级别查询 |
| SkyWalking 覆盖不足 | 链路入口和接口摘要不完整 | 明确已接入和未接入应用，不强制全量补齐 | 一期仅展示接入状态和已接入摘要 |
| Agent 未安装或无心跳 | 服务器资源和日志采集覆盖不足 | 梳理安装状态、版本和心跳阈值 | 未安装主机先通过已有 Prometheus 指标覆盖 |
| Kafka Topic/Consumer Group 归属不清 | 权限裁剪和影响范围不准确 | 由中间件和应用团队共同确认依赖关系 | 共享对象先仅 SRE 可看全局，应用侧展示已确认部分 |
| PostgreSQL 采集账号未准备 | 数据库指标和默认规则无法验证 | DBA 准备最小权限只读采集账号和密钥引用 | 先登记实例和应用依赖，规则保持草稿 |
| 敏感字段口径未统一 | 日志、SQL、连接串、Token 暴露风险 | 安全侧确认首批脱敏字段和默认策略 | 所有敏感明细默认脱敏，明文查看后置 |
| 数据源异常被误判为业务异常 | 误告警、首页健康统计失真 | 明确接入状态和业务健康状态分开展示 | 数据源异常只进接入风险和平台自身告警 |
| 默认阈值缺少业务确认 | Kafka/PostgreSQL/应用规则可能噪音较高 | 周四收集默认规则候选和业务阈值 | P1/P2 核心规则先观察，P3 或高噪声规则不通知 |

## 9. M0 冻结条件

1. ACE、iPro、CMS 应用清单初版可用于资产初始化。
2. 约 20 台服务器清单初版可用于服务器资产和 Agent 状态初始化。
3. Prometheus/Grafana、日志源、SkyWalking、Agent、Kafka、PostgreSQL 至少明确数据源名称、负责人、接入状态、异常原因和补齐计划。
4. Kafka/PostgreSQL 与 ACE、iPro、CMS 的第一批依赖关系有初版。
5. 未接入、部分接入、采集异常、业务异常的展示和统计口径已确认。
6. 所有缺口项均有负责人、预计完成时间和降级策略。
