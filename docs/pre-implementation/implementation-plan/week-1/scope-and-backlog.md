# Sprint 0 第一周交付物：一期范围冻结与 Backlog

## 1. 一期范围冻结结论

一期目标冻结为：完成“看见状态、定位问题、触发通知、基础处理闭环、按应用授权隔离”的核心可用版本，优先服务应用研发负责人，其次服务运维/SRE、值班人员和平台管理员。

一期优先接入范围冻结为 ACE、iPro、CMS 等核心应用，约 20 台服务器，并覆盖 Kafka、PostgreSQL 关键对象；数据源以 Prometheus/Grafana、日志源、少量 SkyWalking、Agent、Kafka Exporter、PostgreSQL Exporter 为主。未接入监控的应用需要在平台内可标记接入状态，并能暴露“未接入、验证中、采集异常、已接入”等状态。

一期功能范围冻结如下：

| 范围项 | 一期结论 | 说明 |
| --- | --- | --- |
| 首页总览 | 纳入 | 以排障视角呈现健康摘要、待处理问题、异常应用、活跃告警、接入异常和跳转入口。 |
| 应用监控 | 纳入 | 支持应用列表、应用详情、实例、接口/运行状态、依赖摘要、日志/指标/告警入口。 |
| 服务器监控 | 纳入 | 支持服务器列表、详情、核心资源指标、Agent 状态、部署应用、当前告警。 |
| 日志中心 | 纳入 | 支持按应用、环境、实例、级别、Trace ID、时间范围查询，支持上下文、错误聚合、脱敏和导出入口。 |
| 指标中心 | 纳入 | 支持指标定义、指标趋势查询、阈值线、告警触发点和从指标创建规则入口。 |
| 告警中心 | 纳入 | 支持简单阈值规则、启停校验、检测调度、去重、恢复、告警事件、确认、处理中、备注、关闭。 |
| 通知与值班 | 纳入基础能力 | 一期正式通知渠道为邮件；支持负责人和值班组作为通知对象，保留其他渠道模型。 |
| 接入管理 | 纳入 | 支持应用接入、数据源管理、Agent 管理、接入校验和接入状态可视化。 |
| 权限与审计 | 纳入 | 权限按应用授权，叠加业务线、环境、菜单、操作、敏感字段权限；关键操作必须审计。 |
| 脱敏与导出 | 纳入验收边界 | 日志敏感字段默认脱敏，导出异步化并受权限、有效期和审计控制。 |
| Kafka/PostgreSQL | 纳入基础监控 | 通过应用依赖、指标中心、告警中心和接入管理承载，不新增独立一级导航。 |
| 平台自身监控 | 纳入上线准入 | API、规则检测、通知发送、数据源查询、审计写入需要纳入监控。 |

一期里程碑采用 12 周建设节奏，Sprint 0 第一周完成 M0：一期范围与接入清单冻结。M0 之后，P0 模块原则上不再扩大范围；新增诉求进入变更评审或二期 Backlog。

## 2. 一期不纳入边界

以下内容明确不作为一期强制交付：

1. 完整 CMDB、集团多公司或完整多租户能力。
2. 完整 APM 拓扑、深度分布式链路追踪和根因分析。
3. 复杂组合规则、动态阈值、智能降噪、完整告警合并策略。
4. 完整静默、完整升级策略、完整排班能力；一期仅保留基础值班组和模型预留。
5. 工单系统、事件管理系统、IM 机器人、短信、电话、企业微信、钉钉正式集成；一期只预留外部事件、Webhook 或回调扩展模型。
6. 自动修复、自动扩容、自动化处理建议。
7. 报表分析、日报/周报/月报、容量预测作为一期强制交付。
8. 中间件监控、数据库监控独立一级导航；Kafka、PostgreSQL 仅做一期基础模板、指标、告警和依赖摘要。
9. Redis、Nginx、网关、任务调度、缓存等专项监控页面。
10. SQL 深度治理、慢 SQL 专项分析、MQ 消息体治理。
11. 完整业务指标平台；一期仅梳理物流、采购场景第一批关键业务指标口径，按优先级接入。
12. 看板收藏、自定义驾驶舱、共享视图、复杂指标对比等体验增强。
