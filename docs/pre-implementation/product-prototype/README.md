# 企业级统一监控平台产品原型设计总览

## 1. 产物说明

本目录用于承载企业级统一监控平台一期产品原型设计产物。原型基于以下输入编制：

- `demand/monitoring-platform-requirements.md`
- `architecture/information-architecture.md`
- `prototype/low-fidelity-prototype.md`

已确认的一期设计约束：

- 核心用户优先级：应用研发负责人优先，其次是运维/SRE，再其次是业务负责人。
- 首页采用排障视角，优先展示当前异常、影响对象、负责人、持续时间和处理入口。
- 告警配置一期支持简单阈值规则，并支持值班组作为通知对象。
- 日志查询一期支持 Trace ID、上下文、错误聚合、日志导出、从告警跳转日志。
- 数据源覆盖 Prometheus/Grafana、少量 SkyWalking，以及未接入监控的应用。
- 权限模型一期按应用授权，日志、指标、告警和关联服务器可见性从应用授权衍生。
- 暂无统一应用资产库和统一 CMDB，一期需要在平台内维护应用、负责人、业务线、服务器和接入状态。
- 一期通知渠道优先使用邮件，其他渠道作为后续扩展预留。
- 日志至少保留 1 个月，部分应用可保留 1 年；敏感字段脱敏策略需可配置扩展。
- 一期支持多业务线独立管理，不要求完整多租户或集团多公司隔离。
- 一期不接入工单、事件管理系统或 IM 机器人，但预留外部集成扩展。
- 一期优先接入 ACE、iPro、CMS 等核心应用，约 20 台服务器，并覆盖 Kafka、PostgreSQL；业务指标优先围绕物流、采购场景梳理。

## 3. 建议评审顺序

1. 先评审核心排障链路，确认“发现异常 -> 告警详情 -> 日志查询 -> 应用详情 -> 指标趋势 -> 回填处理记录”是否顺畅。
2. 再评审配置管理链路，确认告警规则、值班组、通知对象、按应用授权和接入状态是否支撑一期落地。
3. 然后评审列表、查询与状态页，确认筛选、表格、导出、错误聚合、无权限和数据源异常状态是否完整。
4. 最后按验收清单逐项打勾，形成评审结论和遗留问题清单。

## 4. 一期验收重点

- 首页首屏能服务排障，而不是只做管理统计。
- 研发负责人能快速看到自己负责或被授权应用的问题。
- Trace ID 能在告警、日志、应用详情和指标趋势之间传递。
- 告警规则能完成简单阈值配置，并能选择应用负责人和值班组。
- 日志查询支持上下文、错误聚合和受控导出。
- 应用授权能约束应用、日志、指标、告警和关联服务器可见性。
- 数据源状态能区分 Prometheus/Grafana、SkyWalking、仅日志、仅指标、未接入和异常。

## 5. 已确认前置问题与后续细化

| 问题 | 当前结论 | 后续动作 |
| --- | --- | --- |
| 应用资产/CMDB | 暂无统一应用资产库和统一 CMDB，各系统负责人分散维护 | 一期平台内置轻量应用资产与负责人维护；架构设计预留外部资产同步 |
| 一期通知渠道 | 优先使用邮件 | 先完成邮件通知链路、模板和记录；短信、电话、IM、Webhook 作为扩展渠道 |
| 日志保留与脱敏 | 日志至少保留 1 个月，部分应用可保留 1 年；暂无统一脱敏文件 | 日志存储支持应用级保留周期；脱敏规则设计为可配置 |
| 组织隔离 | 需要支持多业务线独立管理 | 权限模型加入业务线维度，并与应用授权组合 |
| 外部系统集成 | 一期不接入工单、事件管理系统或 IM 机器人 | 告警事件、通知事件和处理记录预留 API/Webhook/消息扩展 |
| 一期接入范围 | ACE、iPro、CMS 等应用，约 20 台服务器，Kafka、PostgreSQL，物流/采购业务指标 | 架构阶段补齐正式应用编码、负责人、拓扑、指标口径和阈值 |
