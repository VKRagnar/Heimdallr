# 企业级统一监控平台 UI 高保真阶段研发测试可验收性评审

## 1. 评审结论

| 项目 | 结论 |
| --- | --- |
| 评审范围 | UI 高保真组件清单、核心排障链路页面、配置管理页面、原型验收清单 |
| 最终结论 | 有条件通过 |
| 结论说明 | 当前文档已经覆盖核心页面、主要状态、Trace ID 贯穿、错误聚合、应用授权、值班组选择器、导出确认、审计提示和数据源接入状态，具备进入设计稿绘制的基础。但在可测试落地层面，仍缺少若干统一判定口径、枚举边界、验收数据口径和状态流转约束。建议在绘制前补齐阻塞问题中的字段与交互定义，否则研发和测试容易在权限、导出、审计、数据源异常、告警闭环上产生不同解释。 |

## 2. 总体判断

### 2.1 已具备可验收基础

1. 页面状态具备较完整的测试入口：空、加载、异常、无权限、数据源异常、保存失败、部分缺失、通知失败、未接入、仅日志、仅指标、采集异常等状态均在验收清单或高保真说明中出现。
2. 核心排障链路可拆测试用例：首页、告警详情、日志查询、应用详情、指标趋势之间明确了应用、环境、实例、时间窗口、告警 ID、Trace ID、Request ID、错误签名等上下文。
3. 权限、导出、审计的 UI 表现已经有框架：菜单权限、操作权限、应用数据权限、衍生日志/指标/告警/关联服务器、敏感字段明文、生产权限、导出二次确认、审计提示均有描述。
4. 值班组选择器和应用授权选择器已有高保真级别规格：搜索、筛选、状态、不可选原因、权限预览、批量选择、生产权限确认均有可验收方向。
5. 数据源异常与未接入不是只作为文案出现，而是进入了应用接入、数据源管理、应用详情、日志查询、指标趋势、告警规则等多页面状态。

### 2.2 当前主要风险

当前文档更偏“页面设计说明”和“验收方向”，但部分地方尚未达到研发测试可直接落用例的粒度。风险集中在：

- 状态枚举跨页面虽有提及，但缺少统一状态机和互斥关系。
- 权限与审计的触发时机明确，但缺少审计字段、审计结果回显和失败兜底。
- 导出阈值、脱敏策略、后台任务、失败原因等有描述，但缺少全局一致的可测标准。
- 数据源异常与业务异常的视觉区分已有原则，但缺少聚合状态计算规则。
- 值班组、应用授权选择器的字段基本完整，但仍需补齐选择后对告警规则、通知解析、衍生权限预览的具体验收口径。

## 3. 阻塞问题

| 编号 | 问题 | 影响 | 设计稿绘制前需补齐 |
| --- | --- | --- | --- |
| B-01 | 缺少全局状态字典与状态优先级规则 | 同一对象同时存在业务异常、数据源异常、未接入、无权限、采集延迟时，列表、详情、统计卡、图表可能展示不一致，测试无法判断预期 | 定义对象健康状态、接入状态、数据源状态、Agent 状态、告警生命周期、规则状态的枚举、优先级、互斥/并存关系和文案 |
| B-02 | 权限测试矩阵还未细化到页面控件级 | 文档说明了菜单、操作、应用数据、敏感字段、导出权限，但还缺每类角色在每个页面按钮、Tab、字段、下拉、URL 直访下的明确表现 | 输出角色 x 页面 x 控件的权限矩阵，至少覆盖管理员、运维/SRE、应用负责人、测试人员、值班人员、只读用户、无授权用户 |
| B-03 | 审计可追踪缺少可验收字段 | 多处要求写审计，但测试无法验证审计记录是否完整，也无法判断 UI 是否需要展示审计编号 | 定义审计事件字段：事件类型、对象类型、对象 ID、操作人、操作时间、变更前后、来源页面、审批/确认结果、审计编号、失败原因 |
| B-04 | 导出规则缺少统一阈值与结果状态 | 日志导出、列表导出、指标图片导出的确认、后台任务、失败状态分散描述，容易实现不一致 | 明确导出类型、权限、二次确认条件、行数/点数阈值、字段范围、脱敏策略、任务状态、有效期、失败重试和审计回显 |
| B-05 | 数据源异常和未接入的聚合口径不明确 | 应用列表、首页统计、告警规则、应用详情中“异常、未知、无数据、未接入、采集异常”可能混用 | 定义 Prometheus/Grafana、SkyWalking、日志源、Agent、健康检查异常如何影响应用状态、规则启用、图表空态和首页统计 |
| B-06 | 告警状态流转缺少可执行状态机 | 告警详情已有确认、处理中、备注、转派、关闭等动作，但未明确每个生命周期状态允许的操作、操作后状态和失败回滚 | 补充告警生命周期状态机，覆盖已触发、已通知、已确认、处理中、已恢复、已关闭、已升级、已静默及权限失败、记录失败、通知失败 |
| B-07 | 应用授权选择器的“衍生可见范围”预览口径不够可测 | 选择应用后会影响日志、指标、告警、关联服务器，但未定义预览摘要的计算与边界 | 明确授权后可见对象摘要字段、关联服务器范围规则、生产环境约束、未接入应用授权后的可见/不可操作边界 |
| B-08 | 值班组选择器缺少通知解析验收点 | 当前展示当前值班人、下一值班人、联系方式完整性，但未明确告警触发时如何解析值班组和失败兜底 | 补充值班组解析规则：按告警触发时间解析当前值班人、联系方式缺失处理、备份联系人兜底、停用/排班缺失对规则启用的阻断条件 |

## 4. 非阻塞建议

| 编号 | 建议 | 理由 |
| --- | --- | --- |
| S-01 | 为每个核心页面补一张“状态样例清单” | 高保真绘制时可直接覆盖正常、空、加载、查询失败、无权限、数据源异常、部分缺失，减少遗漏 |
| S-02 | 在设计稿中标注测试数据 ID | 建议为告警、应用、Trace ID、错误签名、数据源、值班组、用户角色准备固定样例，方便研发联调和 UI 验收 |
| S-03 | 增加 URL 直访与越权搜索的验收说明 | 未授权对象不在搜索、下拉、计数、聚合中泄露已有原则，建议明确直访详情页、复制旧链接、浏览器回退的表现 |
| S-04 | 为错误聚合补充归一化说明 | 错误签名、异常类型、接口、实例、Trace 数的展示已明确，但建议说明签名为空、Trace ID 缺失、多应用聚合时的 UI 表现 |
| S-05 | 明确自动刷新与用户操作冲突策略 | 首页和列表有自动刷新要求，建议补充刷新时不覆盖筛选、排序、展开行、抽屉、表单输入、选中行的验收点 |
| S-06 | 补充表单保存失败的字段级错误样例 | 告警规则、值班组、权限、接入、数据源表单都依赖复杂校验，建议设计稿绘制字段错误、分组错误和底栏错误摘要 |
| S-07 | 对敏感字段增加“查看明文后”的状态 | 当前说明了明文查看需授权与审计，建议补充查看成功后展示时长、再次隐藏、复制明文是否允许、审计提示位置 |
| S-08 | 补齐通知记录与通知失败的重试边界 | 通知失败可见已有描述，建议明确哪些角色可重试、重试是否产生新记录、重试中状态如何展示 |
| S-09 | 接入向导建议补充退出与草稿恢复 | 分步抽屉有步骤和必填校验，建议补充中途关闭、保存草稿、验证中离开、重新进入后的状态 |
| S-10 | 为移动端应急处理补最低验收范围 | 文档已有响应式策略，建议明确移动端至少可查看告警摘要、Trace ID、负责人、查日志、确认/备注，不要求完整配置能力 |

## 5. 重点关注项逐项评审

### 5.1 页面状态是否可测试

结论：有条件通过。

可测试点已经覆盖空、加载、查询失败、数据源异常、权限不足、部分缺失、通知失败、告警生命周期、规则状态、接入状态。阻塞缺口在于跨页面统一状态字典和状态优先级尚未明确。设计稿绘制前应确保同一状态在首页、列表、详情、抽屉、弹窗中使用同一文案、图标和操作。

### 5.2 权限

结论：有条件通过。

文档覆盖菜单权限、操作权限、应用数据权限、衍生数据权限、环境权限、导出权限、敏感字段权限、告警处理权限、系统管理权限和审计权限。缺口是没有控件级矩阵，尤其是无权限时“隐藏、置灰、锁定、空状态、无权限页”的选择需要逐页面定稿。

### 5.3 导出

结论：有条件通过。

导出确认、日志导出、指标图片导出、超量后台任务、无权限、失败状态均有说明。绘制前需统一阈值、字段范围、脱敏策略、后台任务状态、有效期和审计编号，否则日志导出、列表导出、指标导出会出现多套体验。

### 5.4 审计

结论：有条件通过。

规则变更、告警处理、权限变更、导出、接入配置、数据源配置、敏感字段查看、密钥查看/更新、值班组变更均要求审计。阻塞缺口是审计字段和审计结果回显方式不完整，建议设计稿中至少体现“审计提示、提交后审计编号、审计入口、失败原因”。

### 5.5 数据源异常与未接入

结论：有条件通过。

Prometheus/Grafana、SkyWalking、日志源、Agent、仅日志、仅指标、未接入、采集异常、验证中均有页面承接。绘制前需补聚合口径：数据源异常是否覆盖业务健康状态，未接入是否进入异常统计，采集延迟是否允许创建规则，Agent 异常是否影响服务器状态。

### 5.6 Trace ID

结论：通过。

Trace ID 在首页、告警详情、日志查询、应用详情、指标趋势中均有字段、复制、查询、跳转和上下文回显要求。建议补充 Trace ID 缺失时的占位文案、复制失败提示、Trace ID 与 Request ID 同时存在时的优先级，但不阻塞绘制。

### 5.7 错误聚合

结论：通过。

错误聚合面板和日志查询首屏均明确错误签名、异常类型、接口、实例、日志次数、Trace 数、首次/最近出现、关联告警和操作。建议补充错误签名为空、多实例同签名、聚合结果受权限过滤后的计数说明。

### 5.8 值班组选择

结论：有条件通过。

值班组选择器已达到高保真绘制基础，包含搜索、筛选、卡片字段、当前/下一值班人、联系方式完整性、规则引用数和不可选原因。阻塞缺口是告警触发时的通知解析和兜底规则，需补齐后才能完整测试规则启用、通知失败和值班变更影响。

### 5.9 应用授权选择器

结论：有条件通过。

应用授权选择器已覆盖业务线、部门、环境、应用状态、接入状态、负责人筛选，已选分组、批量选择和权限预览。绘制前需补齐衍生可见范围的计算说明，尤其是关联服务器、未接入应用、生产环境、敏感权限之间的边界。

## 6. 进入设计稿绘制前检查项

| 编号 | 检查项 | 必须产出 |
| --- | --- | --- |
| C-01 | 全局状态字典 | 状态枚举、颜色/图标/文案、优先级、互斥关系、跨页面使用位置 |
| C-02 | 权限控件矩阵 | 角色、页面、字段、按钮、Tab、下拉、URL 直访、导出、敏感字段的可见/可操作规则 |
| C-03 | 告警状态机 | 状态、允许动作、动作权限、动作后状态、失败提示、处理记录、审计事件 |
| C-04 | 审计事件规格 | 审计字段、审计编号、审计入口、提交成功/失败回显、审计可见权限 |
| C-05 | 导出统一规格 | 导出类型、阈值、字段范围、脱敏策略、二次确认、后台任务、失败重试、有效期 |
| C-06 | 数据源聚合规则 | 各数据源状态如何影响首页、应用详情、指标趋势、日志查询、告警规则、接入管理 |
| C-07 | 值班组通知解析 | 当前值班人解析、备份联系人、联系方式缺失、排班缺失、停用、规则引用影响 |
| C-08 | 应用授权衍生规则 | 授权应用如何衍生日志、指标、告警、实例、关联服务器、生产数据和敏感字段权限 |
| C-09 | 固定验收样例数据 | 至少覆盖 3 个应用、2 个环境、2 个 Trace ID、2 个错误签名、2 个值班组、2 个数据源异常场景 |
| C-10 | 页面状态设计稿清单 | 每个核心页至少绘制正常、空、加载、查询失败、无权限、数据源异常或部分缺失状态 |

## 7. 建议验收口径

设计稿绘制完成后，建议用以下口径进行研发测试验收：

1. 每个页面都能拆出字段验收、筛选验收、操作验收、状态验收、权限验收和跳转上下文验收。
2. 每个关键操作都有成功、失败、无权限、重复提交、审计记录五类验收点。
3. 每个跨页面跳转都能验证来源提示、返回入口、筛选回显和授权过滤。
4. 每个数据源异常都能验证“不误判为业务正常”和“不阻断无关模块查看”。
5. 每个选择器都能验证搜索、筛选、空状态、无权限、不可选原因、选择后预览和保存失败。

## 8. 最终结论

最终结论：有条件通过。

当前 UI 高保真说明可以进入设计稿绘制准备，但建议先补齐阻塞问题 B-01 至 B-08 中的统一规则。若这些规则不补，设计稿仍能画出来，但研发实现和测试验收会在状态优先级、权限边界、导出审计、数据源异常聚合、值班通知解析和应用授权衍生范围上产生较高返工风险。
