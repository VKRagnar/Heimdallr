# 企业级统一监控平台 UI 高保真设计总览

## 1. 产物说明

本目录用于承载企业级统一监控平台一期 UI 高保真设计说明。产物基于需求文档、信息架构、低保真原型和产品原型设计继续细化，目标是支撑后续设计稿绘制、前端页面框架搭建和 UI 评审。

已确认的一期 UI 方向：

- 专业、克制、高密度，服务排障工作台，不做营销化页面或装饰性驾驶舱。
- 首页优先回答：哪里异常、影响什么、谁负责、下一步去哪处理。
- 优先服务应用研发负责人，其次是运维/SRE和值班人员。
- Trace ID、应用、环境、实例、时间窗口在页面跳转中连续保留。
- 告警、日志、指标、关联服务器均按应用授权过滤。
- Prometheus/Grafana、SkyWalking、仅日志、仅指标、未接入、采集异常等状态需要明确区分。

## 3. 建议评审顺序

1. 先评审 `foundation-rules/foundation-rules.md`，确认全局状态、权限、审计、导出、告警状态机和数据源口径。
2. 再评审 `visual-system/visual-system.md`，确认整体视觉方向、状态色和组件密度。
3. 然后评审 `core-pages/core-pages-high-fidelity.md`，确认核心排障链路是否足够短、信息优先级是否正确。
4. 接着评审 `list-pages/list-pages-high-fidelity.md`，确认列表、查询、通知记录和导出任务状态是否完整。
5. 再评审 `config-pages/config-pages-high-fidelity.md`，确认配置、授权、接入和审计是否完整。
6. 最后用 `components-and-review/components-and-review.md` 做逐项检查，形成 UI 评审结论。

## 4. UI 验收重点

- 首屏能在 5 秒内帮助研发负责人判断当前最重要的问题。
- P0/P1/P2/P3、正常、预警、异常、未知、无权限等状态在全平台颜色和文案一致。
- 日志行、Trace ID、错误聚合、上下文、堆栈展示清晰且适合高密度阅读。
- 告警详情的摘要、指标、日志、通知、处理记录在视觉上有明确层级。
- 配置类页面的表单抽屉、校验提示、危险操作确认和审计提示完整。
- 无权限状态不泄露未授权应用名称、日志内容、敏感字段或统计数量。
